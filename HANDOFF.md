## Что это за репозиторий

Два независимых Telegram-бота в одном репо:

- **Корень (`bot_part1..5.py`, `main.py`)** — «утка», оригинальный бот-переводчик.
  DeepL-перевод, доступ по заявкам (whitelist/pending, одобряет админ), TTS
  (gTTS), транскрибация голосовых (Groq Whisper), AI-разбор слов и
  OCR-перевод фото (Groq/Gemini Vision). Работает и был в проде ещё до этой
  сессии.
- **`voicebot/`** — новый бот, сделан «на основе утки» по просьбе владельца.
  Своя папка, свой `Dockerfile`, свои env-переменные — отдельный деплой-юнит,
  не трогает утку. Не имеет системы доступа по заявкам, AI-разбора и OCR —
  это сознательно урезанный функционал под другой флоу (см. ниже).

## Хронология этой сессии (коротко)

1. С нуля построен `voicebot/` — флоу расписан ниже.
2. Все пользовательские тексты приведены к стилю утки («Кря!», 🦆).
3. В пикере языков добавлены названия языков (не только флаги), раскладка
   2 в ряд — как в `/lang` у утки. Раньше было 6 флагов в ряд без подписей.
4. Отдельная сессия прогнала ревью **всего репозитория** (включая
   `bot_part*.py`, которые я не трогал до этого) на ветке
   `claude/code-review-t0ju4a` и запушила фиксы одним коммитом. Эта ветка
   влита в текущую fast-forward'ом (проверено: импорты, pyflakes, ручные
   smoke-тесты хэндлеров voicebot на моках — всё прошло).
5. Деплой на сервер **не выполнялся** — см. раздел «Не сделано».

## Флоу voicebot

- Пользователь шлёт **текст** → бот сразу озвучивает его (TTS определённого
  языка) и присылает голосовым с кнопкой 🌐.
- Пользователь шлёт **голосовое** → бот транскрибирует (Groq Whisper) и
  присылает текст с кнопками 🔊 (озвучить оригинал) и 🌐 (перевести).
- 🌐 открывает пикер языков (флаг + название, 2 в ряд, пагинация по 30):
  - по умолчанию один язык — тап сразу переводит и закрывает пикер;
  - переключатель 🔘/☑️ включает мульти-режим — тапы копят галочки
    (`✅ 🇬🇧 Английский`), кнопка ✅ подтверждает;
  - на каждый выбранный язык — отдельное сообщение с переводом и своей
    кнопкой 🔊.
- Все кнопки — только эмодзи, без текстовых подписей. **Исключение**: сам
  пикер языков — владелец явно попросил добавить названия языков, флагов
  оказалось недостаточно (некоторые страны делят один флаг на несколько
  языков).

Файлы `voicebot/`:
- `main.py` — entrypoint, читает `BOT_TOKEN`/`DEEPL_KEY`/`GROQ_KEY` из окружения.
- `langs.py` — таблица языков, флагов, TTS-кодов; синхронизирована с
  `bot_part1.py` утки.
- `services.py` — перевод (DeepL), детект языка (langdetect → DeepL → Google,
  экономный порядок после ревью), TTS (gTTS), STT (Groq Whisper).
- `handlers.py` — все хэндлеры, in-memory кэши текста и открытых пикеров,
  клавиатуры, access-middleware (`ALLOWED_USERS`/`MAX_TEXT_LEN`/`MAX_VOICE_SEC`).

## Что исправлено ревью-веткой (влито в HEAD, коммит `8f497d5`)

- Ключ Gemini передаётся в заголовке `x-goog-api-key`, а не в URL (утечка
  ключа в текст исключения была исправлена).
- Починен `ImportError` в `/start` (`kb_admin_approve` теперь определена в
  `bot_part3.py` и импортируется оттуда).
- Убран захардкоженный Telegram ID из `is_allowed` в `bot_part1.py`.
- Переводы отправляются как HTML с `html.escape`, а не «сырой» Markdown
  (было: перевод падал с `can't parse entities`, если в тексте `_`/`*`/`` ` ``).
- OCR-текст с фото разбирается многострочно (`_parse_vision_response`),
  раньше терялись все строки кроме первой.
- Доступ ко всем кнопкам (`translate|`, `back|`, `google|`, `speak|`,
  `ai_explain|`, `settings:`) и к заявке (`request_access|`) проверяется
  централизованно, ID берётся из `callback.from_user.id`, а не из
  `callback_data`.
- Вызовы DeepL (включая `get_usage`) идут через `asyncio.to_thread`, не
  блокируют event loop.
- Кэш текста в утке ограничен (было — рос без предела).
- JSON (`users.json`/`langs.json`/`stats.json`) пишется атомарно
  (`_write_json`, через tmp-файл + `os.replace`).
- Мёртвый код удалён (`update_user_info` подключён в `/start`,
  `increment_translation_count` и недостижимая ветка в `/start` убраны).
- `voicebot`: добавлена access-middleware (`ALLOWED_USERS`, пусто = открыт
  всем) и лимиты `MAX_TEXT_LEN`/`MAX_VOICE_SEC`; детект языка сделан
  экономнее (langdetect с порогом уверенности первым, DeepL — по первым 200
  символам, а не по всему тексту — раньше на каждое сообщение уходило вдвое
  больше символьного лимита DeepL, чем нужно).
- `stats.json`/`langs.json` убраны из git (содержали реальные Telegram ID) и
  добавлены в `.gitignore`. Теперь утка ожидает эти файлы в `./data`
  (volume в `docker-compose.yml`, переменные `USERS_FILE`/`LANGS_FILE`/`STATS_FILE`).
- Добавлены `docker-compose.yml` и `.env.example` в корне и в `voicebot/`.

## Не сделано / требует внимания

- **Деплой не выполнен.** У облачной Claude Code сессии нет SSH или иного
  доступа к внешним серверам — только к git-репозиторию. Владелец
  разворачивает сам: `docker compose up -d --build` в нужной папке (корень —
  для утки, `voicebot/` — для нового бота). Токен нового бота у владельца
  уже есть, вводит его сам в `voicebot/.env`.
- **Живых тестов не было.** Всё, что проверялось — импорт модулей,
  `pyflakes`, и ручные smoke-тесты хэндлеров `voicebot` на моках (сборка
  клавиатур, полный флоу мульти-выбора, access-middleware). С реальными
  Telegram/DeepL/Groq/Gemini бот не запускался.
- **Миграция данных утки.** Если утка уже где-то развёрнута и у неё есть
  боевые `users.json`/`langs.json`/`stats.json` — их нужно вручную положить
  в `./data/` до пересборки на новый `docker-compose.yml`, иначе они
  потеряются (переменные путей теперь указывают на `/app/data/...`).
- Не проверено, существует ли модель `qwen/qwen3.6-27b` в Groq API (OCR фото,
  `bot_part5.py`).
- `main.py` утки логирует апдейты целиком (`print(f"[TELEGRAM UPDATE] {event}")`),
  включая текст сообщений пользователей — потенциальная утечка персональных
  данных в лог. Не исправлено ни одной из сессий.
- Код детекта языка/TTS/STT дублируется между `voicebot/services.py` и
  `bot_part3.py`. Осознанно не вынесен в общий пакет — боты остаются
  независимыми деплой-юнитами со своими `Dockerfile`; если решите выносить,
  придётся менять сборку обоих образов.

## Переменные окружения

**Утка** (`.env` в корне, см. `.env.example`):
`BOT_TOKEN`, `DEEPL_KEY`, `GROQ_KEY`, `ADMIN_ID`, `GOOGLE_API_KEY` (опц.,
резерв для OCR), `AUTO_APPROVE` (default `false`), `AI_EXPLAIN_ENABLED`
(default `true`), `AI_PHOTO_ENABLED` (default `true`).

**voicebot** (`voicebot/.env`, см. `voicebot/.env.example`):
`BOT_TOKEN`, `DEEPL_KEY`, `GROQ_KEY`, `ALLOWED_USERS` (опц., ID через
запятую, пусто = открыт всем), `MAX_TEXT_LEN` (default `1000`),
`MAX_VOICE_SEC` (default `300`).

`DEEPL_KEY`/`GROQ_KEY` можно переиспользовать одни и те же для обоих ботов.

## Как проверить локально (без реального Telegram)

```bash
python3 -m py_compile bot_part1.py bot_part2.py bot_part3.py bot_part4.py bot_part5.py main.py voicebot/*.py
python3 -m pip install pyflakes
python3 -m pyflakes bot_part*.py main.py voicebot/*.py
```

Для voicebot есть смысл гонять хэндлеры на моках (`unittest.mock.AsyncMock`)
вместо реального polling — примеры такого прогона были в истории сессии,
покрывают: открытие пикера, переключение мульти-режима, множественный выбор
и подтверждение, кнопку «назад», просроченный кэш/пикер.

## Стиль — сохранять при дальнейших правках

- Все пользовательские тексты — в духе утки: «Кря!», 🦆, игривый тон.
  Ошибки — `❌ ...`, короткие алерты по образцу «Текст устарел. Отправь
  заново.», «Выбери хотя бы один язык!».
- Инлайн-кнопки — только эмодзи, без текстовых подписей. Единственное
  подтверждённое исключение — пикер языков в voicebot (флаг + название).
- Комментарии в коде — по-русски, короткие, объясняют «почему», а не «что».
